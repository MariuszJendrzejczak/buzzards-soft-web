**Drift diagnosis.** The one real drift risk in a comparison table is the negation-contrast
reflex: a difference table *invites* "Start doesn't have X, Full does". The shipped intro
had started down the boundary-description path (*"Granica … przebiega na kontach"*) and
carried a grammar slip (*"Full a Większy różni się"*) plus a colloquialism (*"pieniędzmi"*).
The through-line fix is a single discipline: **describe each tier by what it adds, in
ascending order** — Start (the base scenario) → Full (adds accounts and what follows) →
Większy (adds money + scale). That framing is inherently affirmative (every clause is a
gain), keeps Rule of One (no prices, no feature re-explanation — those live in `pricing`
and `includes`), and reads as a calm peer register rather than a coy boundary metaphor.
No regeneration trials were needed beyond the intro rewrite; the row/column labels were
already clean data labels and passed on the first pass once *colFeature* was de-jargoned.

## Open Questions

1. **`colFeature` label — `"Możliwość"` vs `"Funkcja"`.** I swapped the shipped
   *"Funkcja"* to *"Możliwość"* on register grounds (plainer, more client-facing). If
   the design/table layout relies on the shorter word width, or the owner prefers
   *"Funkcja"*, this is a trivial revert — flagging it because it is the one label I
   changed rather than kept.
2. **Whether `comparison` and `pricing` should both name the Full delta.** This
   section names Full's added features (accounts, loyalty, push, owner panel) as the
   scannable Start→Full delta, and `pricing.full.scope`/`.extras` also lists them.
   That is an intentional label-here / detail-there split (not a Rule-of-One breach),
   but if the landed page renders `comparison` and `pricing` immediately adjacent, the
   owner may want one of the two to drop the feature names to avoid visual echo. A
   layout call, not a copy defect — banked for the human.
3. **Tier column label `"Większy"` (abbreviated) vs full `"Większy projekt"`.** The
   brief fixes `colCustom = "Większy"` (abbreviated to fit a table column), while
   `pricing.custom.name = "Większy projekt"`. Confirmed consistent with the brief; noting
   only so a reviewer doesn't read the abbreviation as a typo against the pricing tier name.
